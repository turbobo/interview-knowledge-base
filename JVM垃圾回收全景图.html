垃圾回收算法 核心算法
标记-清除
原理：标记存活对象，清除未标记对象
优点：实现简单
缺点：产生大量内存碎片
适用：基础算法，很少单独使用
复制算法
原理：内存分两块，存活对象复制到另一块
优点：无碎片，分配高效
缺点：可用空间减半
适用：新生代（存活率低，复制成本小）
标记-整理
原理：标记存活对象，向一端移动，清理边界外
优点：无碎片
缺点：移动对象开销大
适用：老年代（存活率高，不适合复制）
分代收集策略：新生代用复制算法（存活率低）· 老年代用标记-整理或标记-清除（存活率高）
内存分配与晋升机制 基础理论
优先分配：新对象在 Eden 区创建，空间不足时触发 Minor GC
大对象策略：占用大量连续内存的对象直接进老年代；G1 中超过 Region 一半的 Humongous Object 也直接入老年代
年龄晋升：对象存活经过 GC 后年龄 +1，达到 -XX:MaxTenuringThreshold 时晋升老年代
动态年龄：Survivor 区同年龄对象总大小超过 Survivor 空间一半时，≥ 该年龄的对象直接晋升
空间分配担保：Minor GC 前确认老年代剩余空间足以容纳新生代全部对象或历次晋升平均值

GC 类别 Minor / Major / Full
GC 类型回收范围触发条件停顿时间
Minor GC 仅新生代 Eden 区空间不足 较短
Major GC 仅老年代 老年代空间不足 较长
Full GC 整堆 + 方法区 老年代/方法区不足、显式调用 System.gc()、CMS concurrent mode failure 最长
Mixed GC（G1） 新生代 + 部分老年代 老年代占用达到阈值 可控
垃圾收集器演进 从 Serial 到 ZGC
Serial / Serial Old
新生代 / 老年代
单线程收集器，Stop The World 停顿。简单高效，适合客户端模式（-XX:+UseSerialGC）。Serial 用于新生代（复制），Serial Old 用于老年代（标记-整理）。
ParNew
新生代
Serial 的多线程版本，常搭配 CMS 使用。多核环境下性能优于 Serial。
Parallel Scavenge / Old
JDK 8 默认
关注吞吐量（而非停顿时间）。自适应调节策略（-XX:+UseAdaptiveSizePolicy）自动调整堆大小和晋升阈值。-XX:+UseParallelGC 启用。
CMS（Concurrent Mark Sweep）
老年代
JDK 14 移除
追求低停顿的并发收集器。四阶段：初始标记（STW）→ 并发标记 → 重新标记（STW）→ 并发清除。缺点：内存碎片、浮动垃圾、CPU 敏感。
G1（Garbage-First）
JDK 9+ 默认
基于 Region 划分（默认 ~2048 个 Region，每个 1-32MB）。支持可预测停顿（-XX:MaxGCPauseMillis）。Mixed GC 同时回收新生代和部分老年代。Humongous Region 存放大对象。
ZGC
超低停顿
毫秒级停顿（< 10ms），支持超大堆（TB 级）。着色指针 + 读屏障实现并发转移。Java 21 引入分代 ZGC，进一步降低停顿。
选型建议： JDK 8 → Parallel GC（默认） · JDK 9+ → G1（默认） · 超低延迟 → ZGC · 客户端 → Serial GC

核心调优参数 GC 调优速查
-XX:+PrintGCDetails输出 GC 详细日志
-XX:+UseG1GC启用 G1 收集器
-XX:+UseParallelGC启用 Parallel 收集器
-XX:+UseZGC启用 ZGC 收集器
-XX:MaxTenuringThreshold=N晋升年龄上限（默认 15）
-XX:MaxGCPauseMillis=NG1 目标最大停顿时间（ms）
-XX:G1HeapRegionSize=NmG1 Region 大小（1-32MB）
-XX:TargetSurvivorRatio=NSurvivor 期望使用率（默认 50%）
-Xms / -Xmx堆初始大小 / 最大大小
-Xmn新生代大小
-XX:NewRatio=N老年代:新生代 比例（默认 2:1）
-XX:+UseAdaptiveSizePolicy自适应调节堆大小和晋升阈值
