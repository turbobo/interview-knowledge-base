持久化篇 AOF / RDB / 混合
01AOF 持久化
三种写回策略
Always
每次 fsync · 最安全 · 最慢
Everysec
每秒 fsync · 折中 · 最多丢 1 秒
No
OS 决定 · 最快 · 可能丢数据
流程
aof_buf → write → page cache → fsync
AOF 重写
bgrewriteaof 子进程 fork + COW 重写缓冲区 7.0 Multi Part AOF manifest + base + incr
02RDB 快照
触发方式
save 同步阻塞 bgsave 子进程 自动触发条件 save 900 1
核心机制
fork + COW 写时复制 二进制格式恢复快 快照间隔可能丢数据 大内存 fork 阻塞
混合持久化 (4.0+)
AOF 重写 = RDB 全量 + AOF 增量 恢复快 + 丢数据少
03大 Key 影响
对持久化的影响
fork 大页表阻塞主线程 COW 复制大内存 AOF 文件膨胀 监控 latest_fork_usec
优化建议
单实例 < 10GB 纯缓存关闭 AOF 删除用 unlink 异步 关闭 Linux 透明大页

03分布式锁
加锁
SET key val NX EX 30 unique_value 标识持有者 看门狗自动续期
释放锁
Lua 脚本原子 GET+DEL 防误删他人锁
Redlock 高可用锁
至少 3 个独立节点 多数节点加锁成功 总耗时 < TTL Martin Kleppmann 争议
常见陷阱
看门狗无法续期宕机节点 Redlock 性能开销大 锁粒度适中
高可用篇 主从 / 哨兵 / Cluster
01主从复制
全量同步三阶段
psync 协商 → bgsave + RDB → repl buffer 新命令
增量复制 (2.8+)
repl_backlog_buffer 循环缓冲 master/slave offset 断线重连比较 offset 建议 2 倍 平均重连×写入量
关键特性
异步复制 级联复制分散压力 心跳 主10s/从1s 异步可能丢数据
02哨兵 Sentinel
三大职责
监控 PING 检测 选主 自动故障转移 通知 发布订阅
故障判定
主观下线 → 投票达 quorum → 客观下线
故障转移四步
① 选新主（priority→offset→runID） ② 从节点复制新主 ③ 通知客户端 +switch-master ④ 旧主降级为从
部署建议
至少 3 个奇数节点 3→quorum=2 · 5→quorum=3
03Cluster 集群
哈希槽机制
16384 个 slot CRC16(key) % 16384 slot → node 映射 扩缩容只迁移槽
客户端路由
Smart Client 本地计算 MOVED 永久重定向 ASK 临时重定向 Hash Tag {user:1}:name
Gossip 协议
ping/pong/meet/fail 端口 = 业务端口 + 10000 主节点 ≤ 1000
故障转移
pfail 主观下线 15s fail 超半数主节点确认 从节点选举新主 偏向 AP 可能丢数据
部署建议
最小 3 主 3 从 从节点 READONLY 可读
缓存篇 雪崩 / 击穿 / 穿透 / 一致性
01缓存雪崩
原因
大量 key 同时过期 Redis 故障宕机
解决方案
过期时间加随机值 互斥锁重建缓存 后台更新 + 缓存预热 服务熔断限流 高可用集群
02缓存击穿
原因
热 key 过期 大量并发直接查库
解决方案
互斥锁 热 key 不过期 后台异步刷新
03缓存穿透
原因
缓存和 DB 都不存在 恶意攻击 / 业务误操作
解决方案
API 参数校验 缓存空值/默认值 布隆过滤器 位图 + N 个哈希函数
04数据库与缓存一致性
Cache Aside 策略（推荐）
读：缓存命中→返回 | 读：未命中→读DB→写缓存 | 写：更新DB→删除缓存
先更新 DB 再删缓存 vs 先删缓存再更新 DB
先删缓存再更新DB ❌
读+写竞态，旧值被重新加载到缓存
先更新DB再删缓存 ✅
理论有竞态但概率低（缓存写远快于DB写）
保证删除缓存成功
消息队列重试删除 Canal 订阅 binlog 异步删除 延迟双删（不精确） 缓存过期时间兜底
为什么删除缓存而不是更新缓存
删除更轻量 缓存常聚合多表 Lazy Loading 更省资源
